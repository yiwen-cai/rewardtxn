# SQLite 验证阶段结论（2026-09-14）

当前三轮在线验证尚未完成。已证实固定回答下 SQLite 内存模式能降低 CPU RM 成本；尚未证实在线吞吐或准确率改善，也不能将 SQLite 确认为准确率回退根因。

## 已确认的 CPU 结论

固定18个回答batch、576条回答；正式R / DBM / 恢复R对照共21个区块，前三个预热，保留18个。DBM−R耗时差中位数−38.878 ms，95%区块bootstrap区间[−39.631, −38.029] ms，相对降幅21.9%。恢复R−原R为+0.174 ms，区间[−0.530, +0.568] ms。逐项奖励、逻辑记录与实际加载源码核验通过。该结果仅指固定回答CPU RM成本，不代表训练吞吐或质量收益。

证据：[原始计时独立复算](cpu_recomputation.json)、[离线与CPU验收摘要](cpu_acceptance.json)。本次仅保存已有结果，没有重新计时。验收摘要覆盖672,000条历史消费样本、25项解析统计测试、7个真实变体、21,800个原始文件前后不变。

## 恢复阻断与后续

用户已明确要求只重跑最后一轮，前两轮与失败产物保留。首次恢复预检被非目标GPU5的N/A影响；恢复包装器将资源查询限定原GPU1–4后，[目标资源检查](target_resource_check.json)通过，目标卡异常、进程查询异常及查询失败仍拒绝放行，原冻结训练源码未修改。

随后即使Docker明确指定GPU1–4，NVIDIA OCI hook仍报`nvml error: gpu requires reset`；docker run返回125，容器保持Created、Pid=0，内部状态ExitCode=128，不等同于训练进程退出码。见[容器失败证据](container_failure.json)。现场GPU5报告Reset，用户尝试`sudo nvidia-smi --gpu-reset -i 5`返回Not Supported；后者来自用户提供的终端输出，尚未独立复核。尚无重启成功或故障解除证据。故障根因及重启能否彻底解决均未确认。

当前先按用户要求保存结论，不启动新训练。设备恢复后先核查GPU与容器，再接续已授权的最后一轮。现有恢复claim及失败目录已存在，不可直接重跑旧入口或覆盖失败证据，需要整理保留现场的新启动入口。完成500步、退出、导出和终点评估后，再做三轮成本、消费轨迹、质量及R重复噪声比较和独立审计。

单seed、固定顺序与恢复间隔均限制因果解释。已获准的本次可行性例外不代表原候选复审、5%性能门禁及七组smoke通过，旧确认补跑继续暂缓。
