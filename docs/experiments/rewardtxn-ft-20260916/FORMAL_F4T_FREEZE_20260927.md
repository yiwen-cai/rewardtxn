## 现场门槛与资源监测

- 每个配对前使用动态分配入口选择 **任意四张同时空闲且型号一致** 的 H100，并把 UUID 固定给该对两臂。每个 run 前再次确认四卡显存使用不超过 100 MiB、利用率 0%、无计算进程；不能沿用早先空闲快照。
- 训练容器运行期间每 5 秒记录所选四卡的显存、利用率、计算 PID 与本实验容器 PID。若发现外部计算 PID、监测失败或达到该阶段 GPU·小时上限，只停止本实验容器，记录技术无效／预算停跑证据，保留原始文件，不操作外部进程。正式验收要求有监测样本且无违规记录。预算按已有 `cost.json` 的 **四卡训练容器占用时间** 累计，包含技术无效尝试；独立加载和清理成本另列，不把它们隐藏在训练成本中。

## 主判据与停止规则

F4′ 每臂记录故障信号时已完成但未训练的物理评分次数，以及其中以**同一物理评分执行**进入最终保留链的次数。每对先算两臂保留比例，再算 `R 比例 − A 比例`；配对是独立统计单位。仅当预定 10 对全部安全、来源可判定且结果完整，才做双侧精确符号检验，阈值 `p<0.05`，并要求优势方向为 R；零差为平局，完整报告各对比例及中位差。故障后生成 token、评分次数、整 run 时间、GPU·小时和被杀时训练主线程阶段均报告。A 若安全丢弃目标工作，其目标 RTO 无定义；RTO 仅作描述，不计算两臂节省百分比。这一判据替代旧 FT-v1 的 F4 RTO 主检验，仅适用于本轮 F4′。

每对故障命中、训练继续、最终完整状态新进程加载、来源关联与安全性均按现有验收链检查。失败时停在该对并保留全量；技术无效最多一次同 seed、同顺序的整对新目录补做，不能自动跳过或换 seed。有效命中但收益为零照实计入。预算耗尽即停，不追加 seed 追求显著性。F1 后移试点只验工程可达性、在途工作量及恢复链；不做统计，也不自动升级为正式样本。
