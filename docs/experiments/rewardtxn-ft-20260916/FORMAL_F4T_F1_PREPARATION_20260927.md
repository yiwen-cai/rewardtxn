## 工作量与资源草算

有效 F4′ 试点一对耗约 1.79 GPU·h，故 10 对约 18 GPU·h、20 对约 36 GPU·h，均未含技术无效、预检与资源等待。建议把 10 对的硬预算上限设为 **25 GPU·h**（若选 20 对则 **45 GPU·h**）；达到上限停跑并保留已产生的全部结果，不删失失败对。有效 F1 试点两对分别约 1.67／1.70 GPU·h；后移切点的 2 对工程试点建议单列 **5 GPU·h** 上限，时长须据新试点重测。这些是待批准的资源上限，不是已授权用量。既有 `/public` 空间门槛须在每个 run 前重测；若新入口、清理路径或运行条件改变空间峰值，重新测量 `P`。每次仅运行一臂，完整验收后按预定名单保留全量权重，其余通过的 run 先哈希再清理；失败 run 全量保留。

优先争取连续占用固定 4 张卡；若只能共享，正式运行器需在运行中记录其他 GPU 进程，发现争用立即停下并按预定技术无效规则登记。单次启动前空闲检查不足以覆盖试点中实际发生的争用。
